# Семантика языка: что неочевидно и что стоит упростить

## Неявные переменные

Любое присваивание в неизвестное имя **молча создаёт local** (`FunctionCompiler::note` + `collectExpr`). `var` опционален.

**Плюс:** быстрые скрипты, стиль старых BASIC/GS.  
**Минус:** опечатка в LHS = новая переменная, без ошибки. Для «жёсткого» языка лучше opt-in режим или warning в лог.

## Неизвестный идентификатор в выражении

`compileName`: если имя не local, не global, не функция/native — **emit LoadConst null**, без ошибки.

```242:244:src/compiler.cpp
        uint16_t dest = allocTemp();
        emit(Op::LoadConst, dest, addConst(std::monostate{}), 0, 0, 0, expr.line);
        return dest;
```

Это наследие динамических скриптов, но для нового кода — **ловушка**. Читается как «переменная есть, просто пустая».

**Рекомендация:** ошибка компиляции в strict-режиме; в legacy — как сейчас.

## `?name` — не «передан ли аргумент», а гибрид

В VM есть опкод `Op::Passed` (сравнение с `frame.supplied`), но **компилятор его никогда не эмитит** — только `Typeof` или `0`:

```215:227:src/compiler.cpp
    uint16_t compilePassed(const Expr& expr) {
        ...
        emit(Op::Typeof, dest, value, 0, 0, 0, expr.line);
        return dest;
    }
```

Фактическая семантика (см. `test_Typeof`, `test_DefaultParams`):

| Ситуация | Результат `?x` |
|----------|----------------|
| Имя не объявлено | `0` |
| Local/global с значением | **код типа** (`typeCode`), не 0/1 |
| Параметр не передан (слот = null) | `0` → удобно для `if (!?x) x = default` |
| Параметр передан (даже `0`) | обычно ≠ 0 |

Для опциональных параметров это **случайно работает**, потому что «не передан» = null = type 0. Но для локальной строки `?s` даёт `3`, а не «определена ли переменная». Имя `Passed` в AST/опкоде вводит в заблуждение.

**Упростить язык:**

- Ввести явные `passed(x)` / `defined(x)` вместо перегрузки `?`.
- Или эмитить `Op::Passed` для имён из списка параметров текущей функции, а `?` для остального запретить.

## Логические `&&` / `||` без short-circuit

Оба операнда **всегда вычисляются** (`compileLogic` + `Op::LogicAnd`/`LogicOr`). Зафиксировано в `test_NoShortCircuit`.

Это нормально, если задокументировано. C/Java-разработчики будут ошибаться. В `04-simplify-code` можно предложить codegen с `JumpIfFalse` — но **сломает тесты**, только осознанное изменение.

## `true` / `false` как int

Парсер: `Kind::Int` со значением 0/1. В `Value` есть `bool`, но скриптовый мир живёт в int. `State::truthy` понимает и bool, и int.

**Упростить:** везде один скаляр для «логики» (только int) и убрать `bool` из `Value`, либо наоборот — нормализовать в bool при загрузке констант.

## `VOID`, `null`, `NULL`, `NUL`

| Лексема | Поведение |
|---------|-----------|
| `null` / `NUL` | unset value (`monostate`) |
| `NULL` | script pointer (`Pointer`) |
| `VOID` | пустая строка в AST (`Kind::String` без текста) |

Четыре способа выразить «пусто» — legacy, но тяжело для новичков. В ревью API: таблица в `engine.h` или отдельный `LANGUAGE.md` (если решите документировать).

## Индексация строк

- `s[i]` (`GetIndex`) — возвращает **односимвольную строку** (`makeString`), не int.
- `s[[i]]` (`GetChar`) — возвращает **int** (байт).

Два синтаксиса — разумно для GS-стиля, но легко перепутать. Альтернатива: один синтаксис + cast.

## Присваивание «через вызов»

`assignable` включает `Expr::Kind::Call` — для паттерна out-параметров через `var(hours)` → ссылка. Узкий, но важный кейс; без комментария в парсере выглядит как баг.

## Глобальные инициализаторы в исходнике

```156:158:src/parser.cpp
            if (match(Token::Kind::Assign)) {
                parseExpr();
            }
```

Выражение **парсится и выбрасывается**. Значения глобалов приходят из:

1. `#def NAME value` → `SourceUnit.literals`;
2. `initial(GlobalKind)` при `compileUnit` (нули/пустые таблицы).

Строка `int foo = 42;` на уровне модуля **не даст 42**. Если это не задумано — **баг парсера/компилятора**.

## Forward declaration `func a, b;`

Парсер проглатывает объявления, но **не регистрирует** заглушки в `Program.functions`. Работает только как «разрешение использовать до определения», если компилятор не требует символ заранее (текущий codegen — не требует).

## `breakpoint` как statement

Парсится, `expr` сбрасывается в `nullptr`, в compile — пустой `Expr` stmt (no-op). Нет интеграции с отладчиком — мёртвая конструкция или задел. `test_Breakpoint` проверяет только то, что скрипт после `breakpoint` возвращает `1`.

## Дополнение: поведение, которое уже зафиксировано тестами

Менять это без флага совместимости нельзя: тесты кодируют именно такой смысл.

### Блоки не создают область видимости

`test_BlockScope` возвращает `45`: `y`, присвоенный внутри `{}`, виден снаружи. Все локалы функции собираются до кодогенерации и живут весь вызов. `goto` через `var x = ...` просто пропускает запись, слот к этому моменту уже есть и содержит `null`.

### `*n++` — это `(*n)++`

Парсер, увидев `*` перед `++`/`--`, перевешивает инкремент на разыменование:

```549:555:src/parser.cpp
                if (inner->kind == Expr::Kind::PostInc || inner->kind == Expr::Kind::PostDec) {
                    auto deref = makeExpr(Expr::Kind::Deref, op.line);
                    deref->kids.push_back(std::move(inner->kids[0]));
                    inner->kids[0] = std::move(deref);
                    return inner;
                }
```

`test_RefInc`: `bump(&n)` с телом `*n++` доводит `5` до `7`. Записать «сдвинуть указатель» этим синтаксисом нельзя. Имеет смысл оставить семантику и дать переписыванию имя в коде, иначе следующий проход «починит» его до C и сломает `test_RefInc`.

### `>>` логический, сдвиг только на 0..30

`-8 >> 1` в `test_DivMod` обязан быть `2147483644`: сдвиг идёт через `uint32_t`. `1 << 30` считается (`1073741824`), `1 << 31` бросает `shift out of range` (`y >= 31`). Бит 31 сдвигом не поставить, хотя сам сдвиг в беззнаковом 32-битном представлении определён.

### Два `str` и два «нуля» в строке

| Запись | Что получается |
|--------|----------------|
| `str(4)` | буфер из 4 нулевых байт (`test_Constructors`: `sizeof` 4, `strlen` 0) |
| `(str)4` | строка `"4"` |
| `(str)null` | строка `"0"` (каст null идёт как число 0) |
| `toString(null)` у хоста | `"null"` |
| `type(NULL)` | строка `"null"` |
| `typeof(NULL)` | `6` (`test_Typeof` заканчивается на `60`) |

`str(целое)` — аллокатор буфера, `(str)` — преобразование. Отрицательный размер `str` бросает ошибку, неотрицательный молча забивает память нулями.

### `sizeof` / `strlen` / `len`

Для `"hi"` тест ждёт `3:2`: `sizeof` равен `size + 1`, если в строке нет байта 0, иначе равен полному `size` (не позиции нуля). `strlen` режет по первому 0. `len` возвращает сырой размер. `sizeof(ссылки)` всегда `0`, `sizeof(таблицы)` — число элементов.

### Таблица — хендл, `&table` — другой тип

Копия значения таблицы указывает на тот же объект, индексная запись видна вызывающему без `&`. `&table` кладёт в параметр `Reference`. Индексация ссылки не следует за ней (`GetIndex` принимает только string и table) и бросает `value cannot be indexed`. До броска часто не доходит: `sizeof(ref) == 0`, и цикл `for (i = 0; i < sizeof(table); i++)` пустой.

`test_FunctionsChangesContent` ждёт `"n0t1,2,3-n1t1,2,3-"`. `*n++` срабатывает (`n` становится 1), таблица остаётся `{1,2,3}`. Комментарий в `test_script.gs` («n останется 0») уже не совпадает с проверкой в `test_engine.cpp`. Тест зафиксировал обход, в котором out-параметр таблицы ничего не меняет.

`tab(n)` заполняет элементы `null` (`typeof` 0 в `test_Constructors`). `tabresize` растит таблицу целыми нулями (`resizeTable` → `integer(0)`). Два конструктора пустой ячейки.

### Диапазон `for i = a .. b`

Границы включительные: `for i = 1 .. 3` даёт сумму `6`, шаг всегда `+1`. `for i = 10 .. 0` не выполняется ни разу. Конец диапазона **не имеет одного правила** (это уже дефект, подробности в `03`):

| Конец | Прогон при `n = 1`, внутри цикла `n = 10` |
|-------|--------------------------------------------|
| локал `n` | 10 итераций, сравнение читает сам регистр `n` |
| `(n + 0)` | 1 итерация, снимок |
| глобал `gn` | 1 итерация, `LoadGlobal` один раз |

`compileName` для локала возвращает номер регистра, а не копию. Для всего остального заводится временный регистр.

Классический `for (;;)` инициализатор — выражение, не объявление. `for (var i = 0; i < n; i++)` не парсится.

### Аргументы по умолчанию работают только на внутреннем `Call`

`paint()` из скрипта при `fn paint(x)` доходит до `if (!?x) x = 7` и возвращает `7` (`test_DefaultParams`). `engine.call("paint")` без аргументов бросает `wrong number of arguments`, потому что `Machine::run` требует точное число. Натив `call` / `callIndex` идёт тем же строгим путём. Индекс функции у натива `call` — **последний** аргумент: `call(a, b, fid)`. Иной порядок молча даёт `0`.

### `?`, `typeof`, `type`

| Значение | `type()` | `typeof` / `?` | `if (x)` |
|----------|----------|----------------|----------|
| `null` | `"null"` | 0 | нет |
| `NULL` | `"null"` | 6 | нет |
| ссылка | `"ref"` | 0 | да, если хендл жив |
| host-объект | `"object"` | 0 | да |
| `bool` с хоста | `"bool"` | 1 | по флагу |
| скриптовый `true` | `"int"` | 1 | да |
| `""` | `"string"` | 3 | нет |
| `{}` | `"table"` | 4 | да |
| `tab(0)` | `"table"` | 4 | да |

Пустая таблица истинна, пустая строка ложна. Ссылка истинна, даже если за ней `0` или `null`: `if (r)` смотрит на хендл, `?r` даёт код типа `0`. `boolean(true)` с хоста и скриптовый `true` (это `int 1`) в `equals` не равны: `asNumber` bool не разбирает.

`typeName` для `Pointer` проваливается в финальный `return "null"`. Отдельной ветки нет.

### `#def` — сразу макрос и глобал

Непустое `#def NAME text` и подставляет `text` в исходник, и кладёт глобал для `findGlobal`. В скрипте имя раскрывается раньше парсера, поэтому выражение видит текст макроса. Хост через `globalAt` видит результат `rememberLiteral`, а это другой парсер. Прогон:

| Определение | В скрипте | `globalAt` |
|-------------|-----------|------------|
| `#def FLAGS 0b1010` | 10 | 0 |
| `#def SCI 1e2` | 100.0 | int `1` |
| `#def OCT 010` | 10 (лексер, база 10) | 8 (`stol` с базой 0, восьмеричная) |
| `#def N 08` | 8 | 0 |
| `#def NAME` без текста | имя остаётся | глобал `null`, макрос стирается |

`LANG_EMPTY` в `test_Defines` — как раз пустой `#def`: `typeof` даёт 0. Предопределённые `TYPE_INT` и соседние ключи в карту глобалов не кладутся, только в макросы.

Глобалы в таблице сняты через `globalAt`. `FLAGS + SCI` в скрипте дало `110` (float), то есть подставленные `0b1010` и `1e2` лексер прочитал как 10 и 100. `return N` для `#def N 08` дало 8 при глобале 0. Колонка «в скрипте» у `010` — это тот же десятичный лексер (`stoll` по базе 10), отдельным `return OCT` прогон не дублировался.

Экранирование в литерале `#def` тоже расходится. В скрипт вставляется сырой текст, и лексер разбирает `"a\n"` / `'\n'` как обычно. В глобал строка попадает без разбора escape, символ берётся как `text[1]`.

### Библиотека `gs_*` не равна math-библиотеке

`min(2, 9)` после `addMathLibrary` возвращает int `2`. `gs_min(2, 9)` возвращает float `2`. `gs_min` всегда зовёт `realResult`. `sqrt` отвергает отрицательное, `gs_sqrt` нет. `floor` / `gs_floor` даже от целого возвращают float.

`gs_time` возвращает `0`. `gs_rand` возвращает `0`. `gs_random()` возвращает `0`, `gs_random(10, 20)` возвращает `10` (первый аргумент). `println` глотает аргументы и не пишет в `useLog`. В `test_math.gs` функции `test_Random` / `test_RandomRange` есть, `test_engine.cpp` их не вызывает.

### Прочее, что выглядит как опечатка грамматики

- Унарного `+` нет. Особый случай `-2147483648` есть, `+2147483648` нет.
- `++` / `--` умеют имя, индекс таблицы, разыменование и свойство. `s[[i]]++` — ошибка компиляции `invalid update target`. `s[[i]] += 1` компилируется и на прогоне превращает `"Ab"` в `"Bb"`.
- `and` / `or` / `not` — те же операции, что `&&` / `||` / `!`, с той же отсутствующей короткой схемой.
