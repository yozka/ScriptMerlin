# Runtime-ошибки: статус реализации

## Контракт

- `error::Result<T>` наследуется от `T`; `Result<void>` реализован специализацией и default-конструкция означает успех.
- `Engine::call`, `callIndex` и `resume` возвращают `error::Result<Value>`. Ошибка не маскируется обычным `Value::Null()`.
- `NativeFn` и `IScriptObject` не меняют сигнатуры. Callback сообщает о runtime-ошибке через `Engine::RuntimeError(code, text)`.
- `State` фиксирует только первую runtime-ошибку и поднимает флаг. VM проверяет его на ветвлениях, вызовах и возвратах; после callback ошибка также проверяется до продолжения. Ошибка вложенного `Engine::call` фатальна для вызывающего скрипта, даже если callback игнорирует результат.
- `RuntimeError` формирует `Error` с текущими source/function/line/instruction и stack frames, если активный кадр доступен. Вне активного вызова он вызывает assertion в Debug и игнорируется в Release.
- `RegisterFn`, `RegisterFactory` и `Bind` сохраняют assertion-контракт. Ошибка `ResizeTable` проходит через `RuntimeError`.
- `IHandler`, `SetErrorHandle` и `RError` удалены. Ошибки не сохраняются после завершения вызова; C++ исключения не используются для штатного выполнения и не перехватываются.
- Лексер преобразует числовые литералы через `std::from_chars`, без `try`/`catch`.

## Реализовано

- VM helpers для горячих операций возвращают обычные значения и записывают ошибку в `State`; наружные API по-прежнему возвращают типизированный `Result`. Ошибки фиксируются по правилу first-error-wins.
- Контрольные точки VM завершают исполнение с сохранённой ошибкой. Ошибка дочернего `Engine::call` автоматически распространяется в родительский вызов; дополнительные вызовы после контрольной точки не выполняются.
- Ошибочные выходы чистят соответствующий `RunState`; `stop` оставляет его для `resume`.
- Обновлены callbacks стандартной библиотеки, тестовые объекты, console, публичные комментарии и README под новый контракт.
- Добавлены тесты для `Result<int>`/`Result<void>`, first-error-wins, остановки после ошибки callback-а, stack/location, проигнорированной ошибки вложенного вызова и `ResizeTable`.

## Проверки

- Debug, Release, optimized Release и optimized Release с `-fno-exceptions` собираются; все 234 теста проходят во всех четырёх конфигурациях.
- Matched benchmark `Performance.WorkloadSpeed` (50 повторов, `-O3 -march=native -flto=thin`): baseline median 1469.779 µs, текущая версия median 1876.725 µs (+27.7%). Новая схема уменьшает overhead относительно промежуточного `Result`-runtime, но исходные ~1.5 ms пока не восстановлены.
- Поиск в `src/` и `include/`: отсутствуют `RError`, `IHandler`, `SetErrorHandle`, `throw` и `catch`.

## Оставшиеся решения

Поведенческих вопросов не осталось: важные решения подтверждены пользователем. Настройки сторонних библиотек при компиляции с отключёнными exceptions остаются ответственностью интегратора; движок не задаёт их.
