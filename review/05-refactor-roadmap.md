# Приоритетный план

## P0 — исправить или явно запретить

1. **Глобальные инициализаторы** — либо codegen, либо `throw` в парсере при `= expr` на top-level.
2. **`Op::Passed` vs `?`** — выровнять имя и поведение; удалить мёртвый код или использовать для параметров.
3. **Запись `null`** — убрать пропуск в `Move` / `StoreGlobal` / `StoreRef`. Документировать «null не пишет» уже нельзя: прогон показывает мусор во временных регистрах, а не сохранённое старое значение. См. `03`, дефект 6.
4. **`callIndex` invalid** — возвращать ошибку, не `0`. Заодно слить с `Engine::call`: одна арность, один пин результата, одна сборка.
5. **Кадр по RAII** — исключение из `execute` обязано снять свой `RunState`. Иначе после первой ошибки рантайм перестаёт вызывать функции.
6. **Поколение кадра у `Reference`** — индекс в векторе после `return` указывает на чужой слот.
7. **`suspended` не затирать из вложенного `call`.** `resume` после `call` во время `stop` сейчас бросает `script is not stopped`, пауза остаётся в стеке.
8. **Пины `strexplode`** — отметка размера, как в `makeTable`, без `clearAnchors()`. Результат `call` после возврата хосту не укоренён: либо оставить его в `pins` до следующего `call`, либо прямо сказать в `engine.h`, что хендл обязан быть скопирован в глобал или в `anchor` до любой следующей сборки. `toString` по собранному хендлу не должен притворяться значением `null`.

## P1 — снизить число сюрпризов для авторов скриптов

1. Режим **strict locals** (опция Engine): неизвестное имя → ошибка компиляции. Туда же повторный `var` (сейчас молча побеждает второй) и неизвестный `CallName` (сейчас целое `0`).
2. Краткая **спека операторов** в репозитории: `?`, `&&`/`||`, индексы строк, четыре «нуля», `str(n)` против `(str)`, `sizeof` ссылки, `*n++`, логический `>>`, включительный `for ..`, перевод строки после `return`. Пока спеки нет, таблица в `02` — рабочая замена.
3. Улучшить **сообщения парсера** (`spell` для всех `Token::Kind`). Исключения препроцессора обернуть в `sme::Error` с номером строки.
4. **Граница `for i = a .. b`** всегда копируется в регистр один раз.
5. **`+=` / `++` по свойству и `s[[i]]`** вычисляют цель один раз; `++` для символьного индекса либо работает как `+= 1`, либо отвергается тем же сообщением, что и `+=`.
6. **`#def`**: одно значение и для подстановки, и для глобала (общий лексер). `0b` / `1e2` / ведущий ноль не должны расходиться.
7. **Комментарии препроцессора** не режут `` `http://...` ``. Незакрытый `/*` — ошибка.
8. **`type` / `typeof` / `if`** свести к одной классификации, отдельно назвав `NULL`, ссылку и host-объект.
9. **NaN** в `<=` / `>=` не равен. **`%` для `INT_MIN` и `-1`** обрабатывается рядом с делением. **`(int)` от float** вне int32 — ошибка, не `static_cast`.
10. **Арность.** Либо `Engine::call` принимает недостающие аргументы как `null` (как `Op::Call`), либо скриптовый вызов тоже строгий. Смесь ломает `?param` ровно на границе с игрой.
11. **`load`** либо документировать как «добавить функции поверх старых глобалов», либо сбрасывать глобалы этого юнита, пины и пустой `runStack`. Сбрасывать кадр посередине `stop` без явного API не стоит.

## P2 — упростить сопровождение C++

1. Слить switches в VM; убрать `dispatchExtra`.
2. Общий парсер литералов preprocess + lexer.
3. Карта имя → индекс функции для `CallName`.
4. Keywords `tab`/`ref`/`ptr` в лексер.
5. Таблица нативов вместо копий `gs_abs` / `gs_min` / `gs_floor`. Заглушки `gs_random` / `gs_time` / `println` пометить как заглушки или вывести в лог.
6. Убрать пустой include `state.h` из `ast.h`. `Expr::Kind::Bool` и `Op::Passed` удалить, когда поведение `?` зафиксировано (пункт P0.2).
7. `useLog` звать из места, где ошибка уже поймана (`call` / `resume`), раз `State::fail` мёртвый.
8. Не разворачивать `vector<unique_ptr<Slot>>` в плоский вектор: адреса объектов должны переживать рост кучи.

## Что не трогать без веской причины

- Неявное объявление переменных — завязано на массу `.gs`.
- Регистровая аллокация с reset `watermark_` на каждый statement — неэффективна, но стабильна, пока запись `null` честная. Сам сброс watermark без обнуления слотов — часть дефекта 6, его не надо «оптимизировать», его надо перестать читать как мусор.
- Синтаксис `[[i]]` для байт строки — покрыт тестами.
- `*n++` как инкремент значения по ссылке, логический `>>`, включительные границы `for ..`, `sizeof` строки `size+1`, `str(n)` как буфер, отсутствие short-circuit, отсутствие блочной области видимости. Всё это уже утверждено `tests/test_engine.cpp`.
- Правую ассоциативность `=`.

## Какие тесты добавить вместе с починкой

Существующий набор эти дыры не видит. Минимальный набор, который их закрывает:

- `x = null` и `id(null)` после выражения, которое заняло временные регистры;
- `typeof` элемента таблицы, в который только что записали `null`;
- `&` локала, сохранённый в глобал, затем другой вызов с собственным локалом в том же слоте;
- вызов после скриптового `1/0` (движок должен снова работать);
- `call` другой функции во время `stop`, затем `resume` первой;
- `anchor` до `strexplode` и строка, возвращённая предыдущим `call`;
- `for i = 1 .. n` при изменении `n` внутри, рядом с `(n + 0)` и с глобалом;
- `` `http://example` ``, `#def` с `0b` / `1e2` / `08` и сравнение скрипта с `globalAt`;
- `self().v += 1` считает вызовы `self` один раз;
- `n <= n` для NaN ложно.
