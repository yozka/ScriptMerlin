## Краткий вердикт

Язык — **прагматичный C-подобный DSL** под игровые/скриптовые сценарии: регистровая VM, неявные `var`, ссылки, препроцессор `#def`/`#include`, хостовые объекты. Тесты (`tests/ver2/*.gs`, `tests/test_engine.cpp`) хорошо фиксируют намеренное поведение (в т.ч. **отсутствие short-circuit** у `&&`/`||`).

Главные проблемы не в «не компилируется», а в **скрытой семантике** (неизвестное имя → `null`, `?` смешан с `typeof`), **дублировании** (комментарии, поиск функций), **мёртвом опкоде** `Passed`, и **незавершённых путях парсера** (инициализаторы глобалов).

Разделы «Дополнение» в остальных файлах проверены отдельным прогоном `Engine::loadSource` на текущем дереве (не полным `ctest`). Самые дорогие дефекты:

1. **`Move` / `StoreGlobal` / `StoreRef` не пишут `null`**, а временные регистры между операторами не обнуляются. `id(null)` после арифметики возвращает мусор; `typeof` от null-элемента таблицы возвращает тип того, что осталось в слоте аргумента.
2. **Ссылка на локал после `return`** то кидает `dangling reference`, то молча читает регистр нового кадра с тем же индексом (прогон дал `7` вместо `42`).
3. **Исключение из скрипта не снимает `runStack`.** После 64 ошибок движок отвечает `script call nested too deeply` даже на исправную функцию.
4. **`call` во время `stop` гасит `suspended`**, `resume` больше не находит паузу.
5. **Хендл, который вернул `call`, не переживает следующий `call`.** `anchor` сборку переживает, пока его не сотрут: `strexplode` в конце вызывает `clearAnchors()` и вместе с этим отпускает якоря хоста. `toString` по уже собранному хендлу возвращает строку `"null"`.
