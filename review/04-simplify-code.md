# Упрощение кода (C++)

Без изменения наблюдаемой семантики тестов, если не указано иное.

## Лексер (`lexer.cpp`)

| Сейчас | Проще |
|--------|--------|
| `kKeywords` как `unordered_map<string>` | `static constexpr` sorted array + binary search, или `string_view` + perfect hash — меньше аллокаций на идентификатор |
| Дублирование `scanChar` / `scanString` escape | Одна `readEscape(char quote)` |
| `scanNumber` + `stoll`/`stof` на уже собранном тексте | По возможности парсить число в один проход без `std::string text` для int |
| Спецкейс `2147483648` в лексере и парсере | Один хелпер `parseIntLiteral(text, line)` |

## Парсер (`parser.cpp`)

1. **`isDeclKeyword` + `declKind`** — объединить в одну функцию `optional<GlobalKind> parseDeclKind()`.
2. **Типы `tab`/`ref`/`ptr` как идентификаторы** — добавить в keyword map лексера (`KwTab` и т.д.), убрать сравнение строк в парсере.
3. **`parseGlobalDecl`** — если инициализаторы не нужны, **не вызывать** `parseExpr()` (быстрее и честнее); если нужны — сохранять в AST.
4. **Правая ассоциативность присваивания** — `parseExpr` рекурсивно парсит RHS как expr (`a = b = c`). Если не задумано — `parseTernary` или отдельный уровень `parseAssign`.

## Компилятор (`compiler.cpp`)

1. **`compileCall` / `compileList`** — копирование аргументов в `[watermark_, watermark_+n)` через `Move` каждый раз. Можно выделить `emitArgs(span<uint16_t> regs)` и переиспользовать.
2. **`binaryOp`** — `And`/`Or` падают в `return Op::Add` при ошибке (мёртвый default). Лучше `unreachable()` / throw — fail fast.
3. **`compilePassed`** — переименовать в `compileQuery` и удалить мёртвую ветку с `Op::Passed` или реализовать её.
4. **Двухпроходность** — `collect` дублирует обход дерева. Можно объединить с codegen при одно pass + forward declare locals (сложнее) или оставить, но вынести обход в `visitStmt`/`visitExpr`.

## VM (`machine.cpp`)

1. **Гигантский `execute()`** — разбить на `execOp(Op, Instruction&, Frame&, Chunk&)` по файлам или таблица указателей на handlers (как switch, но по функциям) — читаемость.
2. **`dispatchExtra` + второй switch** — слить в один `switch (ins.op)`; сейчас часть опкодов в «extra» без причины.
3. **`CallName` lookup** — при `compileUnit` построить `unordered_map<string, uint32_t>` function index; в chunk хранить только index (как `Call`). *Меняет только производительность.*
4. **Повтор `state().runStack.back().frames.back()`** — локальные ссылки `Frame& frame` уже есть; в лямбдах `bump`/`write` использовать их.

## Engine / State

1. **`typeName` + `typeCode`** — дублируют классификацию. Один внутренний `enum class ValueTag` → string/code.
2. **`findFunction` / `call`** — общий `lookupFunction(string_view) -> optional<uint32_t>`.
3. **Natives** — вектор + параллельный `nativeNames`; хранить `struct Native { string name; NativeFn fn; }` одним вектором.

## AST (`ast.h`)

- `Expr::Kind::Bool` не используется парсером — удалить или начать использовать.
- `Stmt::ForC` vs `For` — нормально; можно переименовать в `ForRange` / `ForClassic` для читаемости.

## Препроцессор (`preprocess.cpp`)

- `rememberLiteral` дублирует логику лексера для чисел/строк — **общий модуль literal parsing** (один файл `literal.cpp`).
- `stripComments` почти копия лексера — для `runText` можно вызывать тот же код (функция в `lexer` namespace internal).

## Heap (`heap.cpp`)

- `kCollectAt = 32` — вынести в константу конфигурации Engine или считать от `slots_.size()` с долей свободных.
- При collect всегда `slot.data = std::string{}` — для Table/HostBox лучше `slot.data = monostate` через `Object{}` или `destroyObject(slot)`.

## Тесты

- Кэш `cachedEngine` в тестах скрывает порядок загрузки — ок для unit, но при рефакторинге compile стоит добавить **отдельные тесты компилятора** (ожидаемый opcode sequence) — сейчас всё через интеграцию .gs. Общий `Engine` на файл ещё и ядовит: тест, который оставил `runStack`, `stop` или стёр `pins`, портит следующие проверки в том же процессе.

## Дополнение

Правая ассоциативность `a = b = c` совпадает с C. Выносить присваивание из `parseExpr` ради «простоты» не нужно.

### Одна запись в регистр

Три одинаковых `if (!monostate) return;` в `Move`, `StoreGlobal`, `StoreRef` — это и есть дефект 6 из `03`. Удаление проверок короче любой новой семантики «null значит не трогать» и чинит аргументы, тернарный оператор и `typeof`. `SetIndex` уже пишет безусловно; после выравнивания особый случай исчезнет.

Снимок границы `for` — один `Move` во временный регистр перед циклом. Пока `Move` пропускает `null`, этот снимок врал бы на null-границе, поэтому сначала запись, потом снимок.

### Один адрес у цели присваивания

`store`, `compileModify` и `compileUpdate` по три раза разбирают имя / индекс / свойство / разыменование / вызов. Отсюда двойной `self()` в `obj.prop += 1` и отказ `s[[i]]++`.

Один помощник достаточен: вычислить цель один раз и вернуть пару «прочитать в регистр / записать регистр». `++`, `--` и `+=` становятся обёрткой над ней. Отдельные ветки `Index` и `Deref` в `compileModify` после этого не нужны.

`var(index)` в `compileCall` сейчас сначала копирует аргументы в новые слоты, а `RefGlobal` читает старый регистр. Спецслучай стоит поставить до копирования. Натив с именем `var` всё равно недостижим: проверка текста идёт раньше `CallNative`.

### Стек вызова как RAII

`Machine::run` и `resume` должны держать кадр объектом, который в деструкторе снимает свой `RunState`, если функция вышла по исключению. Это короче, чем `try/catch` в каждом нативе у хоста, и чинит дефект 8. Флаг `suspended` логично вывести из верхнего кадра (`ip` стоит сразу за `Stop`), а не хранить вторым источником правды, который вложенный `call` затирает.

`Engine::call` и `callIndex` — одна функция: поиск уже сделан снаружи, дальше общий путь арности, пина результата и сборки. Сейчас `callIndex` при плохом индексе возвращает `0` и не собирает кучу, `call` бросает и собирает.

### Пины как стек отметок

`makeTable` уже сохраняет размер `pins` и обрезает его. `strexplode` должен вызвать тот же приём и не звать `clearAnchors`. Публичный `clearAnchors` для хоста можно оставить, но стандартная библиотека им пользоваться не должна.

### Один разбор литерала

`rememberLiteral` дублирует лексер и расходится с ним (`0b`, `1e2`, ведущий ноль, escape, исключения `stol`). Проще не парсить значение второй раз: макрос остаётся текстом, а начальное значение глобала получается тем же `lex`, что и исходник. `#def NAME` без текста по-прежнему только объявляет глобал.

`stripComments` знает только двойные кавычки. Пока директивы режутся отдельным проходом, этот проход должен считать строками `"`, `` ` `` и `'`, либо препроцессор должен вызывать лексер и смотреть директивы по уже готовым токенам. Второй вариант убирает и held-token комментариев, и порчу URL в backticks.

Исключения `std::stol` / `std::stof` на границе препроцессора оборачивать в `sme::Error` с номером строки. Сейчас наружу лезет `stol: no conversion`.

### Нативы одной таблицей

`installGsLibrary` — сотни одинаковых лямбд. Достаточно массива `{имя, арность, функция}` плюс общие `asInt` / `expectNumber`. `abs` и `gs_abs`, `min` и `gs_min` должны звать одну реализацию: сегодня `min` сохраняет int, `gs_min` всегда возвращает float, `sqrt` проверяет знак, `gs_sqrt` нет.

`gs_time`, `gs_rand`, `gs_random`, `println` лучше сделать явными заглушками в одном месте (или не регистрировать), чем функциями, которые притворяются библиотекой. `println` логично отдать в уже существующий `useLog`; сейчас логгер не подключён ни к чему, потому что `State::fail` никто не вызывает.

### Классификация значения один раз

`typeName`, `typeCode`, `truthy`, `equals`, `toString` каждый по-своему обходят `variant`. Один `switch` по типу (включая `Pointer`, ссылку, host-объект и bool) отдаёт имя, код и «пусто или нет». Сейчас `type(NULL)` — строка `"null"`, `typeof(NULL)` — `6`, host-объект по коду неотличим от `null`.

`bool` в `Value` скрипт сам не производит (`true` компилируется как int). Либо хостовый bool при входе приводится к int, либо `equals` / `asNumber` начинают его понимать. Две параллельные правды дороже, чем одна ветка.

### Мелочь, которая уменьшает файл

- Убрать `#include "state.h"` из `ast.h`.
- `Expr::Kind::Bool` парсер не создаёт. Либо удалить вид, либо начать класть туда `true` / `false` и не притворяться, что в VM есть скриптовый bool.
- `Op::Passed` не эмитится. Удаление опкода и переименование AST-вида короче, чем поддержка мёртвой ветки в `dispatchExtra`.
- `group_` / `braceExpr_` и held-newline — уже в прошлом разделе. Новый токен скобки снова придётся учесть в `account`, `lookingAtCast` и в ручном пропуске newline у строк. Один режим «внутри скобок newline не токен» в лексере снимает счётчики с парсера.
- `spell()` по-прежнему отвечает `"token"` почти на всё. Таблица `Token::Kind → текст` на ~40 строк окупается на первой же ошибке разбора.
- Платформенные `.cpp` не упрощают VM. Пока `platformName` ни на что не влияет, не плодить туда логику скрипта.
